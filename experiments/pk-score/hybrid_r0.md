# 形状スコアとBPP補正の統合、交差補助変数の簡約

refinementを切った状態で、形状とBPP補正の統合スコアは新しい300配列のPK対F1を0.231560から0.243064へ上げた。差の95%対応bootstrap区間は `[+0.002187,+0.025555]`、デコーダ時間は1.64倍だった。整数目的値を保つ補助変数の簡約も実装したが、主条件で減った変数は約0.5%で、高速化は確認できなかった。

手動のH型形状スコアにBPPの支持と相手特異性を加える実験と、整数解の目的値を保ったまま補助変数を減らす実験を行った。構造全体に対する学習は今回の対象に含めない。

## 統合するスコア

二つの固定最大ステムブロックの長さをA、B、H型の三つのループ長をL1、L2、L3とし、以前の手動形状スコアを使う。

```
s = -0.05 + 0.025 min(A,B) - 0.0075 Σ log(1+Lr)
w = γ s/(A B) + λ d/anchor_length
d = θ・f
```

wは、二つのブロックに属する異レベルの交差塩基対が同時に選ばれた接点ごとの係数。形状とBPPの項を加えてから既存の交差スコア定式化に渡すため、二つのスコアのために補助変数を二組作ることはない。ブロック内の全A×B接点が成立すると、形状項の合計はγs、BPP項の合計はλd×弱ステムの長さになる。

主導ステム（anchor）は、BPPから計算した平均支持が高い方とする。同値の場合は長さと座標で決め、レベルの上下とは区別する。全体のBPP支持が高いステムを足場に、弱い方のステムを一対ずつ補正する以前の正規化を維持する。fは以前の12特徴のうち、切片と以下の七つだけを使用する。

| 特徴 | 定義 |
|---|---|
| anchor_support、weak_support | 各ステムの平均 `p/(1+p)` |
| weak_min_support | 弱いステムの最小 `p/(1+p)` |
| support_product | 二つの平均支持の積 |
| support_gap | 主導側の平均支持−弱い側の平均支持 |
| weak_specificity | 弱い側の各対について、最強の別相手との比 `clip(log((p+1e-6)/(q+1e-6))/4,-1,1)` の平均 |
| anchor_specificity_product | 主導側の平均支持×弱い側の相手特異性 |

qは、対象の対を除いた両端それぞれの別相手のうち強い方。候補cut前の初期BPPから求め、各塩基の上位二相手を保存して使う。`p/(1+p)` は既存特徴と同じ有界変換であり、新しく校正したPK確率ではない。四つの形状特徴の学習係数は0に固定し、手動形状と二重に学習させない。

θは以前と同じ調整用bpRNA282配列、同じ類似性クラスタの五分割、同じRNA単位で重みを揃えた局所logistic損失で学習する。3160ブロック例、例がある178配列を使用し、残る104配列を調整精度から除外しない。正解ラベルは二つのステム内の正解対占有率の積で、構造全体の予測誤差を最小化する学習ではない。正則化0.01/0.1、選択済み誤接点の重み1/4から五分割のloglossで選び、今回は0.01、1が選ばれた（logloss 0.2759953）。切片は正解占有率の事前平均0.08381587のlog oddsを引いて中心化する。

係数は [posteriorモデル](models/hybrid-r0-v1-posterior.txt) に保存する。初期BPPから12特徴を独立に再計算し、native出力との最大誤差0を確認した。固定ブロックを使い、maxstem/maxloopは200/200、候補cutは通常のまま、自動閾値選択へのスコア直接加算は0とする。γ=0/0.5/1、λ=0/0.005/0.02/0.05の格子を調整し、補正0も選択肢に含める。`--pk-h-weight` がγ、`--pk-learned-scale` がλに対応する。

採点するのは実際に成立した交差接点だが、形状は候補ブロックから事前計算したもの。両ステムの全対の成立や、三つのループが実際に全て未対合であることまでは要求しない。部分選択時は成立した接点だけを加算する。BPPにない強制対を含むブロックでは学習項を0とし、定義できる形状項だけを残す。

## 整数目的値を保つ簡約

ある上位対の変数をx、ある下位レベルで交差する**元の全候補**をy1,…,ymとすると、元の支持制約は `x ≤ Σyr`。以下の両条件を満たす行だけで簡約する。

1. 全候補に同じ非ゼロ係数cがある。採点外の候補や0係数候補が一つでも混ざれば簡約しない。係数の比較は許容誤差を使わない完全一致。
2. 全候補が一つの塩基を共有する。元の塩基対排他制約から `Σyr ≤ 1` が成り立つ。候補が一つの場合も含む。

すると二値のx、yrについて、`x Σ(c yr) = c x`。x=0なら両辺0、x=1なら元の支持制約と排他性でΣyr=1だから成立する。cが負でも同じである。この項をxの目的係数へ直接加え、その行のスコア用連続変数とリンク行を作らない。元の交差支持行・候補・整数変数は残す。

これは選択済み接点の積を近似する操作ではない。全ての許容整数構造について採点値を保つ。LP緩和の形と分枝限定の進み方は変わるため、変数を消した数に比例した高速化は保証しない。該当しない行では従来通り、元の支持行につき最大一つの連続変数と最大四つのリンク行を使う。簡約は `--pk-crossing-simplify` で明示的に有効にし、デフォルトはオフ。

## 評価の分離と計測

全条件 `-r 0`、LinearPartition-C、一スレッドHiGHS、自動閾値10候補。各RNAの初期BPPを一度だけ保存し、全設定が同じ行列を使用する。新しい300配列では直接FASTA入力と保存BPP入力の基準予測、および10グラフの特徴出力が一致することを事前に確認する。

調整用は以前と同じ282配列（PK陽性141、PKフリー141）。17設定を比較し、統合・形状のみ・BPPのみの三系列からそれぞれ、全対F1を下げず、PKフリーの偽PK RNA数を増やさない条件でPK対micro F1を最大化する設定を選ぶ。主比較は統合系列の勝者。調整時に選ばれたのは統合γ=1/λ=0.05、形状のみγ=1、BPPのみλ=0.05。調整基準PK対F1は0.186333、各勝者は0.192467、0.187254、0.190692だった。

さらに以前の手動スコア（`legacy`）とR0全特徴モデルを対照に入れ、それぞれ簡約の有無も測る。legacyは以前の部分ステム列挙、maxstem12/maxloop30、閾値選択への直接加算1を維持する。一方、新しい形状のみ・統合モデルは固定最大ブロック、200/200、直接加算0。したがってlegacyとの精度差をBPP項の追加だけの効果と解釈しない。統合と新しい形状のみの比較は、同じブロック・形状係数・閾値選択規則でλだけが違う。

評価用は [ZenodoのIPknotデータセット](https://zenodo.org/records/4923158) のRfam14.5から新たに300配列（PK陽性150、長さビンを合わせたPKフリー150、長さ12〜200）を抽出した。以前に観測した全1782配列との完全一致、さらに大域編集距離による80%以上の類似配列を除外する。今回の300配列の類似性クラスタは300。RNA家族を分離した標本ではない。

格子・学習・サンプリング・失敗処理の規則を先に保存し、調整結果から重みと12評価条件を固定した後に新しいスコア予測を始める。テスト結果に合わせて重みを変更しない。

各条件を同じRNAで逐次実行し、条件の順序をRNA・反復ごとに巡回させる。三反復のRNAごとの実時間中央値を合計する。BPP計算・キャッシュ確認・学習を時間から除き、通常のモデル読込、閾値探索、定式化、求解、出力は含める。精度はRNAごとに一度数え、900観測を900独立RNAと扱わない。95%区間は類似性クラスタを単位とする5000回の対応bootstrap、seed 20261003。主比較以外と、簡約速度の区間は探索的で、多重比較は補正しない。

各試行は20秒でタイムアウトとし、自動再試行しない。同じ設定・段階で三回のタイムアウトが出れば残りを明示的な未実行として記録し、全配列が揃わない設定に完全標本の精度や区間を出さない。

## 簡約の精度と速度

全ての簡約あり／なしの組合せで、300配列の予測は同一だった。各閾値の最適目的値ログ（12有効桁）の最大差も0。数学的な同値性の証明と、小規模整数割当のoracleに加え、実データの結果でも一致を確認できた。

| 統合 | 29.190→29.294秒 | 1.00356 | [0.99366,1.01323] | 77 / 231 |

| 以前のR0全特徴モデル | 29.688→29.641秒 | 0.99843 | [0.98976,1.00759] | 77 / 231 |

主条件で簡約が発生したのは16/300配列。全閾値グラフの追加連続変数15236個のうち77個（0.505%）、追加行48011行のうち231行（0.481%）を削減した。これらは逐次構築した全グラフの合計で、同時に15236個の変数を持つモデルを作ったという意味ではない。各RNAの閾値探索での最大変数数を合計すると、簡約あり／なしはどちらも5680個で、全体の最大値110個も変わらなかった。削減は、最も大きい閾値グラフでは生じなかった。

元の全交差候補の係数が一致し、かつ全候補が一つの塩基を共有する条件は、実データでは少ない。最大ブロック内の複数対を同時に選択できる通常のステムは、この排他条件に当てはまらない。厳密な簡約は正しく働いたが、主条件では高速化を確認できず、以前の手動スコアではわずかに遅くなった。変数・行が減ることを理由に自動的に有効化する設定にはしない。

## 結果の適用範囲

今回の主比較は、PKを半数含む長さ200以下の標本での改善を支持する。長いRNA、自然なPK出現率、RNA家族を分離したデータでの改善は未検証。前の300配列で精度を見てから今回の方針を選んだこともあり、実験を重ねて探索した範囲全体に対する多重比較補正ではない。初期BPPの通常のcutを通らない正解対は復活できず、固定ブロック内にない交差も今回のスコアでは採点できない。

精度が上がった代わりに1.64倍の求解時間が必要だった。簡約でこの増加を解消することはできなかった。したがって、統合スコアは有望なオプトインの実験条件として残し、デフォルトは変更しない。構造全体に対する学習は後日の課題のままとする。

## 再現

native推論の主条件：

```sh
./build/ipknot -r 0 -t auto,auto \
  --pk-h-formulation crossing --pk-h-allocation blocks \
  --pk-h-max-stem 200 --pk-h-max-loop 200 --pk-selection-weight 0 \
  --pk-learned-model experiments/pk-score/models/hybrid-r0-v1-posterior.txt \
  --pk-learned-scale 0.05 --pk-hybrid-shape \
  --pk-h-intercept -0.05 --pk-h-stem-reward 0.025 --pk-h-loop-penalty 0.0075 \
  --pk-h-weight 1 --pk-crossing-simplify input.fa
```

このコマンドに実験スナップショットは不要。`--pk-h-weight 0` でBPPのみ、`--pk-learned-scale 0` で形状のみ、両方0で補正0になる。簡約の比較は `--pk-crossing-simplify` だけを外す。全ての新機能はオプトイン。

全比較の再実行は [hybrid_r0.py](hybrid_r0.py) のprepare→train→cache→tune→freeze→testと、[summarize_hybrid_r0.py](summarize_hybrid_r0.py) の監査・集計を使う。Pythonは標準ライブラリだけで動く。

```sh
python3 experiments/pk-score/hybrid_r0.py prepare --output /tmp/pk-hybrid-replay
python3 experiments/pk-score/hybrid_r0.py train   --output /tmp/pk-hybrid-replay
python3 experiments/pk-score/hybrid_r0.py cache   --output /tmp/pk-hybrid-replay
python3 experiments/pk-score/hybrid_r0.py tune    --output /tmp/pk-hybrid-replay
python3 experiments/pk-score/hybrid_r0.py freeze  --output /tmp/pk-hybrid-replay
python3 experiments/pk-score/hybrid_r0.py test    --output /tmp/pk-hybrid-replay
python3 experiments/pk-score/summarize_hybrid_r0.py \
  --output /tmp/pk-hybrid-replay --publication /tmp/pk-hybrid-replay/publication
```

準備にはMD5 `01f491361b31b4520f5fd527d4ad5cbf` の `/tmp/ipknot-dataset.zip`、以前の四実験のmanifest、R0実験の初期BPP・neutral特徴・ログ・fingerprintが必要。これらはresults以下のローカル実験スナップショットであり、コンパクトな集計だけをgitに保存する。既定のバイナリは `build/ipknot`。別のバイナリは各段階と集計に `--binary PATH` を指定する。別出力先では新しいfingerprintを作り、以前の結果を上書きしない。

Release、GCC13.3、ARM64、HiGHS1.15.1、ViennaRNA2.7.2。バイナリSHA256は `131006de80f6be2a4b059612909e87337738e4d60941272c089da41f8e4a5de3`、モデルSHA256は `f0cc53ede91372d35e632548f429a8d475fbf348f81415cfbcf963d0f6ca9578`。

60件のCTestを通過。符号付き係数、二・三レベル、部分占有、ゼロ係数、採点外の交差候補、BPPにない強制対について、許容整数割当と目的値を列挙したoracleを簡約の有無で検証した。CLIでは形状とBPPの独立尺度、ゼロ補正、相殺、簡約ログ、不正な混用を確認した。
