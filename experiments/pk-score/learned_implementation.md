# BPPの支持と相手特異性を使う学習交差スコア

既存の交差制約を利用し、候補ステム対の形状に加えてBPPの支持と対合相手との競合を採点する。モデルを指定した場合だけ有効になる。基準版の整数変数・候補塩基対・BPP計算・求解呼び出しは増やさない。交差支持行あたり高々一つの連続補助変数と四行を使う。

## nativeで採点するもの

各閾値の候補塩基対の和集合から、最大の連続ステムブロックを作る。H型のスパンを持つ二ブロックについて、平均支持 `c=p/(1+p)` が高い方をアンカーA、もう一方をBとする。同点では長さ、座標の固定規則を使い、最適化後のレベルや正解構造を参照しない。

12次元の特徴を `f(A,B)` とし、ファイルに保存した係数thetaと調整用データで選んだ尺度lambdaから `delta=lambda*theta^T*f` を計算する。二本の塩基対の交差接点には `delta/|A|` を割り当てる。したがって選択された対数が `kA,kB` なら、寄与は `delta*(kA/|A|)*kB`。アンカーが全て選ばれた場合に、Bの選択対一つあたりdeltaが入る。どちらのステムが上位レベルでも同じ配分になる。

同時に選ばれた交差対だけが加点・減点の対象になる。全ステムの選択やループの非対合状態は要求しない。形状は入力候補の最大ブロックで決まり、未選択の延長を含む場合がある。複数のアンカーからの補正は加算されるため、一対への厳密な総補正上限や成分全体の物理エネルギーではない。

特徴は次の固定定義。長さの特徴には `min(1,log1p(n)/log(13))`、ループには `min(1,log1p(n)/log(31))` を使う。係数の内積を最適化後にclipする処理は入れていない。

| 名前 | 定義 |
|---|---|
| bias | 1 |
| anchor_support / weak_support | A/Bの平均 `p/(1+p)` |
| weak_min_support | Bの最小支持 |
| support_product / support_gap | 両平均支持の積 / A−B |
| weak_specificity | Bの相手特異性の平均 |
| anchor_specificity_product | Aの平均支持×Bの相手特異性 |
| min_length / weak_length | 短い方 / Bの対数長さ |
| outer_loop / middle_loop | 両外側ループの対数長さの平均 / 中央ループの対数長さ |

相手特異性は `clip(log((p+1e-6)/(p_alt+1e-6))/4,-1,1)`。`p_alt` は、当該対を除いて両端から選べる最強の相手の値。疎行列に代替相手がない場合の0は、真の物理確率が0だという意味ではない。refinementは条件付き値を加算し、pが1を超える場合があるので、生のlogit(p)は使わない。

各BPP行列につき一つのcontextを作り、端点の上位二相手を集計し、閾値探索で再利用する。物理ステムの集計もcontext内で一度だけ計算する。疎BPPのmap構築に `O(P log P)`、特徴内積に定数12の計算が加わる。既存の最大ブロック・交差接点の列挙はそのまま使う。目的係数とLP緩和が変わるため、求解時間が不変になるとは限らない。

`--pk-feature-output FILE` は、候補座標・特徴・選択対数をTSVへ追記する診断用機能。単独で使う場合は重み・補助変数を作らない。補正尺度0または全係数0のモデルは特徴計算も省略する。NMRで強制された対にBPPがない場合、そのブロックの補正を省略してカウンタに記録し、元の制約は保持する。

## 学習と評価の手順

前回と同じbpRNAの282配列（PK陽性141、PKフリー141）から、基準版の自動閾値・refinement1の各段階を出力した。5,640グラフ、8,294ブロック対、193配列が特徴を持つ。残り89配列も精度集計から除外しない。中身を選ばれた構造から作り直すのではなく、実際の候補最大ブロックを使う。

教師は、各ブロック内の正解対の占有率の積 `gA/|A|*gB/|B|`。RNAごとに総重みを揃えた正則化ロジスティック回帰で学習する。これは物理的なステム対の局所的な教師であり、レベル制約を含む厳密な条件付き確率やF1の変化ではない。候補グラフで利用可能なレベル別接点は、その直積の一部だけになる場合がある。実現可能な参照構造への投影とloss-augmented decodingを使うSSVMは今回実装していない。

係数の切片から、調整用のRNA均衡な平均教師のlog-oddsを引き、平均的な候補に対する正負の相対補正とする。この出力はエネルギーでもPKを含む同時確率でもない。整数計画法の目的係数への尺度は、通常のデコーダで別途調整する。

形状のみ、形状＋絶対BPP支持、さらに相手特異性二特徴を加えた全モデルを比較する。調整用配列を類似性クラスタごとの五分割にし、正則化0.01/0.1と、基準版が選んだ不完全な接点の重み1/4を検証する。その後282配列の実際のデコーダで尺度0.005/0.02/0.05を比較し、全塩基対F1を下げず、PKフリー配列の偽PK数を増やさない条件でPK対F1が最大の設定を選ぶ。補正0も選択肢に含める。

以前使った1,182配列を全て除外し、さらに `1−Levenshtein_distance/max_length >= 0.8` の配列を除いた新しいRfam 300配列（PK陽性150、長さビンを合わせたPKフリー150）で評価する。この基準は大域編集距離に基づく配列分離で、アラインメントの一致率やRNA家族の分離とは異なる。過去の配列との比較で追加除外は10配列。家族IDがないため、家族にまたがる一般化を証明する評価とは扱わない。

特徴、重み、尺度、コードとバイナリのSHAを固定してから新しい評価を実行する。条件ごとに逐次実行し、各配列三回の中央値で時間を測る。PK対F1と全対F1はmicro集計、差の区間は配列類似性クラスタ単位の対応bootstrap 5,000回。失敗・タイムアウトは記録し、欠落した配列を黙って精度集計から外さない。

## 調整結果

調整用の交差接点教師に対する、クラスタごとの五分割検証のlog lossは、形状0.268658、絶対BPP追加0.260601、相手特異性追加0.256312だった。三モデルとも正則化0.01、選択済み不完全接点の重み1が選ばれた。局所教師の識別改善が、最終デコーダのPK精度改善を保証するわけではない。

各モデルの調整用PK対F1が最良の設定は全て尺度0.05。形状のみが選択された。新しい評価で勝者を選び直さない。

### 採点範囲の制限

[native候補の診断](measurements/learned-native-diagnostics.json)では、neutral exportの最終予測が以前の基準版と282配列全てで一致した。12,231個の幾何的に適格なブロック対のうち、3,937個は異なるレベルに配置できる塩基対の組合せがなく、特徴出力・採点の対象から外れる。8,294個の出力は完全正解234、部分正解498、正解接点ゼロ7,562だった。これは繰り返しの候補出現数であり、独立したモチーフ数ではない。

基準版の全20グラフにある物理ブロックスパンの和集合は、正解交差接点1,365/8,204、正解PK対449/2,370（18.95%）を覆う。一方、基準版が最終的に選ぶ正しい接点688/697、誤った接点3,762/4,122を覆う。誤った接点4,122のうち2,460は、片側に正解の通常対またはPK対を含む。単独対のPKラベルでなく、相手と両方正しいかを学習する理由になる。

現状の採点範囲は、既に予測される誤交差の抑制に向く。候補最大ブロックの未選択延長や重なり、BPPと候補cutの欠落により、正解構造を覆う選択済みステムより範囲が狭い。この19%は基準版の候補に対する記述統計で、学習補正によるrefinementの変化後の回復率の上限ではない。またレベル別接点を全て出力していないため、物理スパンの被覆率は実際に同時成立可能な採点接点の過大評価になる。

広い回復範囲が必要なら、既存の疎な交差支持辺を直接採点する方式を別条件で検証する必要がある。適用範囲を増やすと連続変数や非ゼロ係数の実数も増え得る。今回の評価にはこの変更を混ぜていない。

## 未使用300配列での結果

6条件×300配列×3回、5,400実行が全て成功し、各条件の三回の予測は一致した。補正尺度0のモデルは300配列全てで基準予測と一致した。[設定・結果・対応bootstrap](measurements/learned-crossing-summary.json) と [実験プロトコル](measurements/learned-crossing-protocol.json) に全条件を保存した。

時間は、配列ごとの三回の中央値の合計。学習・特徴出力の時間を含まず、通常のモデル読込、BPP、refinement、閾値探索、求解を含む。ARM64、GCC 13.3、HiGHS 1.15.1、ViennaRNA 2.7.2、LinearPartition-C、一スレッド。

| 凍結した条件 | 全対F1 | PK対F1 | PKフリー150配列の偽PK数 | 合計時間 | 基準比 |
|---|---:|---:|---:|---:|---:|
| 基準 | 0.650261 | 0.230856 | 69 | 34.439秒 | 1.000 |
| 調整で選択：形状のみ・0.05 | 0.652734 | 0.238333 | 68 | 50.476秒 | 1.466 |
| 絶対BPP追加・0.05 | 0.652677 | 0.241684 | 69 | 52.764秒 | 1.532 |
| 相手特異性追加・0.05 | 0.653121 | 0.240398 | 69 | 49.312秒 | 1.432 |
| 以前選んだDP：b=0.05、lambda=0.002 | 0.650738 | 0.228687 | 68 | 41.516秒 | 1.205 |
| 学習補正0 | 0.650261 | 0.230856 | 69 | 34.544秒 | 1.003 |

PK対F1差の95%区間は、形状のみ `[-0.005318,+0.022372]`、絶対BPP追加 `[-0.000576,+0.025155]`、相手特異性追加 `[-0.003544,+0.024654]`、DP `[-0.015153,+0.007214]`。全対F1差の区間も全て0を含む。改善傾向は出たが、安定した精度向上を確認したとは言えない。テストで点推定が高かった絶対BPPモデルへ、選択モデルを変更していない。相手特異性を加える独立した利得も確認できなかった。

選択した形状モデルでは、PKの正解対511→526、誤PK対1,646→1,618、変更された予測23/300。相手特異性モデルでは正解対532、誤PK対1,624、変更24/300。新しいテストでも局所教師のlog lossと最終PK対F1は一致しなかった。

追加整数変数は0。最大の連続補助変数93、追加行334、採点されるレベル別交差辺1,610。実際の最適化呼び出しは各条件合計5,964（配列ごとの中央値の合計）、一配列最大20回で、今回は条件間でも一致した。ただし別の配列では、補正によってrefinementのBPPが変わり、空候補の閾値が増減すれば実際の最適化回数は変わり得る。閾値グリッドとrefinement回数を追加する実装ではない。

追加の連続変数と制約が求解を難しくし、今回の短い配列群では合計時間が約1.43〜1.53倍になった。形状対の特徴内積だけを安く計算しても、整数計画法全体の時間は不変にならない。既定のスコアは無効のままとする。

実験で選択したモデルを使うコマンドは次の通り。`--pk-h-max-stem` と `--pk-h-max-loop` は採点範囲で、予測する構造の長さ制限ではない。実験では両方200、通常の既定は12/30なので、同じ設定で使う場合は明示する。

```sh
build/ipknot -r 1 -t auto,auto \
  --pk-learned-model experiments/pk-score/models/learned-v1-shape.txt \
  --pk-learned-scale 0.05 --pk-selection-weight 0 \
  --pk-h-max-stem 200 --pk-h-max-loop 200 input.fa
```

全12特徴の比較モデルは `models/learned-v1-all.txt`、絶対BPPモデルは `models/learned-v1-absolute.txt`。いずれも尺度0.05で事前に凍結した比較条件で、汎用の推奨パラメータとしては扱わない。

## 長い配列での時間検証

以前に使った実配列508/615塩基を、凍結した形状モデル・全特徴モデル・基準版で各三回測定した。通常のFASTA/refinement1/自動閾値と、以前保存した共通の初期BPP/refinement0/固定閾値の二条件、36実行が全て成功した。新しいBPPのキャッシュ生成や重み調整は行わず、キャッシュ・元の参照・モデル・ソースのSHAを検証した。これは既知の二配列での補足時間測定であり、新しい精度評価ではない。[詳細](measurements/learned-runtime-summary.json)。

| ワークフロー | 長さ | 基準時間 | 選択した形状モデル | 全特徴モデル |
|---|---:|---:|---:|---:|
| FASTA・refinement1・自動閾値 | 615 | 1.021秒 | 1.309秒（1.28倍） | 1.314秒（1.29倍） |
| 同上 | 508 | 3.620秒 | 8.860秒（2.45倍） | 7.646秒（2.11倍） |
| 共通BPP・refinement0・固定閾値 | 615 | 0.0878秒 | 0.1115秒（1.27倍） | 0.1013秒（1.15倍） |
| 同上 | 508 | 0.3972秒 | 0.4761秒（1.20倍） | 0.4593秒（1.16倍） |

508塩基の通常ワークフローでは、最適化時間が3.266→8.484秒（形状モデル）、モデル組立が約0.009秒で、主な増加は求解だった。補正によってrefinement後の候補も変わるため、共通BPPでの差とは同じ比較ではない。全条件でFASTAは20回、固定閾値は1回の最適化だった。最大追加連続変数214、追加行732、採点交差辺4,732。二例だけから長いRNA一般の時間倍率は推定しない。

## 再実行

データは [元のIPknot++データ公開](https://zenodo.org/records/4923158) のZIP（MD5 `01f491361b31b4520f5fd527d4ad5cbf`）。元の調整用manifestと過去の評価manifestは `results/calibration` と `results/energy-implementation` に置く。

```sh
python3 experiments/pk-score/learn_crossing.py self-check
python3 experiments/pk-score/learn_crossing.py prepare
python3 experiments/pk-score/learn_crossing.py export
python3 experiments/pk-score/learn_crossing.py train
python3 experiments/pk-score/learn_crossing.py tune
python3 experiments/pk-score/learn_crossing.py test
python3 experiments/pk-score/analyze_learned_native.py
python3 experiments/pk-score/check_learned_runtime.py
```

別の出力先を使う場合は全段階へ同じ `--output DIR` を渡す。既存の記録とコード・データ・設定が一致しなければ停止する。モデルの形式は `IPKNOT_PK_LINEAR_V1` に続く、上記12個の名前と係数の行。欠落・未知名・重複・非有限値はエラーになる。`--pk-learned-model` はcrossing/blocksを既定で選び、自動閾値選択へのraw補正の重みは既定0とする。

学習係数は [models](models)、学習・標本の集計は [learned-crossing-training.json](measurements/learned-crossing-training.json) と [learned-crossing-samples.json](measurements/learned-crossing-samples.json)。実装の59件のテストが通り、線形化の符号・部分選択・レベル交換・欠測・ゼロ補正・従来のNMR機能を確認した。
