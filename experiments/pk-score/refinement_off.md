# refinementなしでのPKスコアの再評価

これまでの主要な精度実験は `-r 1`、すなわちrefinement一回を使っていた。初期の保存BPPによる小規模比較と、長い二配列の固定閾値時間測定だけが `-r 0` だった。目的係数の変更が次のrefinementのBPPにも影響するため、これまでの改善を初期BPP上のPKスコアだけの効果とは解釈できない。

再評価の結果、未使用300配列で主比較のR0学習モデルはPK対F1を0.225717から0.228703へ上げたが、差の95%区間は `[-0.001455, +0.008993]` で0を含む。計算時間は1.63倍。DP・CCはPK対F1を上げず、現時点でPK精度が確実に上がるスコアは確認できなかった。

今回の実験では全てのデコードを `-r 0` とする。各RNAの初期LinearPartition-C BPPを一度だけ計算して保存し、全てのスコア設定に同じ行列を渡す。保存時の有効桁数をfloatのround-tripに必要な9桁へ修正し、直接FASTAからの基準予測と保存BPPからの基準予測が一致することを全RNAで確認する。学習用282配列については、12特徴を保存BPPから独立に再計算してnativeの出力とも比較する。

## 比較する設定

過去に宣言した82設定を、同じnativeパラメータ・テーブル・モデル係数の組合せでまとめると69設定になる。[全設定と出典](measurements/refinement-off-inventory.json) に保存した。過去の係数、採点範囲、候補cut、スコアを自動閾値選択へ反映する係数を変更せずに再評価する。

| 系列 | 採点対象 | refinementなしでの解釈 |
|---|---|---|
| level penalty | 上位レベルに置いた対 | PK対の総数を抑える単純な対照 |
| exact | 両ステムとループの成立 | 成立条件を保つ形状補正。求解負荷も測る |
| projected | 上位対の目的係数 | 相手候補の形状から配分した一対ごとの近似補正 |
| supported | 上位対の目的係数と交差支持制約 | スコアに加えて許される支持相手を狭める条件として分けて記録 |
| crossing | 同時に選択した異レベル交差対 | 既存の交差支持行を利用する形状補正 |
| rerank | 自動閾値探索で得た構造 | 初期BPPから得た候補構造の選び直し。固定閾値では予測を変えない |
| DP / CC | 固定最大ブロック内の選択済み交差接点 | エネルギー由来の形状補正を目的係数へ配分 |
| 学習モデル | 交差ブロックの形状・BPP支持・相手特異性 | R1で学習済みの係数を固定する条件と、R0で学習し直す条件を分ける |

候補cutを広げる三設定、supportedの五設定、ゼロ補正の四設定は、純粋なスコア変更とは区別する。通常の候補cutを保った比較でも、目的係数の変更によってLP緩和・分枝限定の難しさが変わるので、求解時間は不変とは仮定しない。

## データと評価手順

調整用は以前と同じbpRNA282配列（PK陽性141、PKフリー141）。全69設定の再評価に加え、R0で学習し直した形状・絶対BPP・全特徴モデルの三尺度を比較する。学習には同じ五分割と類似性クラスタを用い、評価用配列の正解は使わない。

以前の学習スコア評価で使ったRfam300配列について、事前に指定した20代表設定を自動閾値と固定閾値 `0.125,0.0625` の両方で再評価する。この300配列は既知データであり、新しい独立評価とは呼ばない。R1との対応比較は、同じ配列・同じ設定の既存実行記録がある条件に限る。

R0での設定選択は調整用282配列だけで行う。PK対micro F1を最大化し、全対micro F1を基準より下げず、PKフリーRNAの偽PK数を増やさない条件を用い、補正0も選択肢に含める。系列ごとの勝者が補正0の場合にも、最良の非ゼロ設定を診断として残し、不成功を見えなくしない。

過去の全1,482配列と同一の配列を除き、さらに `1−Levenshtein_distance/max_length >= 0.8` の配列を除外して、新しいRfam300配列を事前に抽出する。PK陽性150と長さビンを合わせたPKフリー150を用いる。大域編集距離による分離であり、RNA家族の分離を保証するものではない。

新しい300配列での予測前に、コード・バイナリ・入力BPP・モデル係数・設定選択を固定する。時間は逐次実行した三回のRNAごとの中央値を合計し、BPP計算とキャッシュ確認の時間はデコーダ比較から外す。通常のモデルやテーブル読込、閾値探索、モデル構築、求解は含める。対応bootstrapの区間は、同じ類似性クラスタを単位に計算する。

調整結果が全て揃う前に、検証が完了したprimary系列の勝者から調整用PK対F1が最大の一設定を主比較として選ぶ規則を別途保存した。候補拡張・制約変更・エネルギーの対照条件は主比較から除外する。主比較には通常の95%区間を使い、他の系列・特徴モデル間の比較は多重比較を補正していない探索的な結果として扱う。

失敗・20秒のタイムアウトは実行ごとに記録し、自動で再実行しない。失敗したRNAを黙って精度の分母から除外せず、不完全な設定は完全な設定と同じ精度表に載せない。

exactの最初の一設定では、167配列の時点で20秒のタイムアウトが14件発生した。この実測に基づき、未使用300配列での設定選択より前に、同じ設定で三回のタイムアウトが出た場合は残りを明示的な未実行として記録する基準を追加した。該当設定は全配列の精度を集計できないため、新しい300配列での三回測定にも送らない。改訂前のコード・プロトコル・fingerprint・学習由来を保存し、BPP、ネイティブの採点、係数、閾値を変えずに実行管理だけを改訂した。改訂時の中断で保存できなかった進行中の試行は、保存実行記録の総数には含めず、プロトコルに記載した。

## 初期BPP上の採点範囲

[R0候補の診断](measurements/refinement-off-coverage.json)では、調整用282配列の10閾値の物理ブロックスパンが、正解交差接点1,340/8,204（16.33%）、相手も正しい交差を持つ正解PK対434/2,370（18.31%）を覆う。単にブロック内に含まれる正解PK対は639/2,370（26.96%）であり、同時に採点できる交差の被覆率とは異なる。

基準版の最終予測にある正しい交差接点630個のうち605個（96.03%）、誤った交差接点3,983個のうち2,049個（51.44%）を覆う。以前のR1の全20グラフでは誤交差の91.27%を覆ったので、今回の初期BPPだけの評価は採点範囲も異なる。

これらは物理ブロックスパンの統計で、レベル別の採点辺や同時実現可能性を確認した被覆率ではない。実際の採点範囲を過大評価し得る。また採点した対の変更は他の対の選択にも影響するので、18.31%を予測回復率の厳密な上限とは解釈しない。

CC系列の勝者は補正0。R0の全特徴モデルは、全体F1と偽PK数の条件を満たす系列の中で調整用PK対F1が最大だったので、主比較に固定した。手動stem_mediumとの差は小さく、この調整用の順位だけから汎用の優位性を判断しない。

[同じ282配列上の過去R1記録との比較](measurements/refinement-off-tune-r1-comparison.json)では、47の同一設定、51の過去研究記録を対応させた。基準PK対F1はR1が0.192986、R0が0.186333だが、基準に対するstem_mediumの増分は `+0.007192 / +0.007434`、DPの増分は `+0.003418 / +0.003532` と近い。以前の全特徴学習係数の増分は `+0.002496 / +0.005807` だった。

弱いCC rerankの増分はR1の `+0.007813` からR0の `−0.000466` へ変わった。同じCC採点範囲に一定値0.025を置く対照と、R1/R0の両方で予測が一致する。これまでのCC rerankの改善を、初期BPP上のCCの形状依存性による改善とは解釈できない。

対応表には各過去R1実験のバイナリSHAと設定の一致証明を保存した。今回のR0条件は全て同じバイナリで比較し、直前の学習スコア実験からのネイティブ差分はBPP出力精度だけ。過去の時間はBPPとrefinementを含むため、今回の保存BPPデコーダ時間との比を求解速度の比較には使わない。

保存BPPの特徴と予測のround-tripを含む60件のCTestが通った。ネイティブの採点・制約・refinementの実装は変更せず、BPPの出力精度だけを修正した。

## 再現

公開データは [ZenodoのIPknotデータセット](https://zenodo.org/records/4923158)（ZIPのMD5 `01f491361b31b4520f5fd527d4ad5cbf`）。ビルドはRelease、HiGHS一スレッド、LinearPartition-C、デコーダのSHA256は `3a57a203cf7346ca7261073f7dc57de30ad6083cf9f103109155ed50d1d6e955`。

主比較のR0モデルをFASTAへ直接適用する例：

```sh
./build/ipknot -r 0 -t auto,auto \
  --pk-h-formulation crossing --pk-h-allocation blocks \
  --pk-h-max-stem 200 --pk-h-max-loop 200 --pk-selection-weight 0 \
  --pk-learned-model experiments/pk-score/models/learned-r0-v1-all.txt \
  --pk-learned-scale 0.05 input.fa
```

全比較の入力と処理順序は [プロトコル](measurements/refinement-off-protocol.json) と実行スクリプトに保存した。完全な再実行には、過去三実験のmanifest・モデル・テーブル、今回の実験スナップショット、R1との対応用の `prior-r1-summary.json` を揃える準備が必要になる。この履歴集計は新しい出力先のprepare処理では生成されない。

また、学習アダプタと実行管理は既存の公開済み集計JSONとの不一致を拒否する。異なる出力先ではfingerprintも変わるため、全比較を再実行する際は、集計JSONの公開先を分けた作業コピーを使う。保存した結果と学習証跡を保護するための制約である。上のnative推論コマンドは、この実験スナップショットの準備を必要としない。

スコアはデフォルトでオフのまま。このPKを半数含む、長さ200以下の標本は自然な配列分布を表さず、RNA家族を隔離した評価でもない。有限のスコア・尺度の比較であり、DP/CCの完全な熱力学モデルやPK塩基対確率を検証した実験ではない。
