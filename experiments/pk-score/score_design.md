# 現在の交差スコア実装に合わせたPKスコアの設計

最初に試す候補は、**交差する相手が選ばれた場合の、塩基対一つあたりの正負の補正を学習するモデル**。DP/CCの形状項に対し、対合相手との競合と二本の支持の組合せを追加する。8〜12程度の特徴と既存の交差辺重みで表現できる。精度向上はまだ検証しておらず、以下は実装前の設計と調整用データの診断である。

## 誤予測から得た根拠

前回と同じbpRNA調整用282配列（PK陽性141、PKフリー141）だけを使い、既存の予測と新しく出力した初期BPPを解析した。前回評価した300配列を特徴・係数の選択に使っていない。

基準予測のPK塩基対は2,107対、正解432、誤り1,675。誤PK対のうち425対は、正解構造では通常の塩基対だった。単独では正しい対が、誤った相手と交差してPKと分類される。このため、単独対の「正解PKか」というラベルより、交差する二対の同時正解ラベル `y_a*y_b` が今回の目的関数に合う。

| 基準予測の選択済みステム対 | 正しい交差接点 | 誤った交差接点 | 接点の精度 |
|---|---:|---:|---:|
| 短い方が2対 | 106 | 1,628 | 6.1% |
| 短い方が3対以上 | 591 | 2,481 | 19.2% |
| 中央ループ0 | 100 | 1,128 | 8.1% |
| 中央ループあり | 597 | 2,981 | 16.7% |

選択された連続ステムで定義するH型スパン相互作用376個のうち、両ステムが全て正解なのは20、部分正解は19、正解接点ゼロは337。短いステムの信頼度は有用そうだが、長さ特徴だけの補正は以前にも試して改善が確認されていない。中央ループ0や短い外側ループへ一律に加点する根拠も得られていない。これらの特徴の符号は、競合・BPPとの条件を含めて学習する。

初期BPPと、最終refinement後の基準予測のPK対を比べると、正解432対・誤り1,675対のうち初期BPPに出力されている対について、初期BPP中央値は0.3932・0.3220、相手特異性の中央値は1.4132・0.8365だった。観測された対で両端の最良の対合相手である割合は90.3%・83.5%。特異性だけでも誤PKは多く残るので、相手ステムとの相互作用が必要になる。

これらは選択構造に基づく記述統計。376相互作用や接点は独立な標本ではなく、長いステムでは接点数も大きい。選択済みステムと、実際のnative候補の最大ステムは異なる。統計だけから係数や一般化精度を決めない。

### 候補と配分の制限

初期BPPの最小自動閾値0.0625を超える正解PK対は1,451/2,370=61.2%。出力された疎BPP（cut 0.001以上）には2,008/2,370=84.7%が存在する。残り362対は出力されておらず、真の確率0と仮定しない。refinementで候補が変わるので、61.2%は最終候補の被覆率や精度の上限ではない。最終まで候補に入らない対はスコアだけでは回復できない。

選択構造のH型スパンは、正解PK対の93.4%と基準予測PK対の99.4%を覆う。ただし空ループは要求せず、三本以上のステムも許すため、前回の厳密なpure H型の被覆率とは異なる。正解交差成分151個中115個は三本以上のステムを持つ。H型ステム対のスコアを足しても、成分全体の物理エネルギーにはならない。

さらに、非ゼロDP条件の最終PK補正が0の18配列中17配列には、選択構造上のH型スパンがある。その選択形状をDPで採点すれば非ゼロになる。最大候補ブロックの未選択延長やレベル別変数の配置、正負の相殺などにより、寄与がゼロになる可能性がある。原因の確定には実際の各閾値・refinement候補グラフの出力が必要。

既存14条件の出力を正解を見て配列別に選ぶoracleのPK F1は0.22617（基準0.19299）。既存出力のrerankで得られる余地はあるが、これは新しくデコードする構造の上限ではない。

詳細は [score-native-errors.json](measurements/score-native-errors.json) と [score-evidence.json](measurements/score-evidence.json)。前者のnative候補BPP未保存という注意は前回実験時の各閾値・refinement候補を指し、今回出力した初期BPPは後者で別に扱う。

## 推奨する補正

候補ブロックU,Vのうち、入力の支持が強い側をA、弱い側をBとする。例えば平均P/(1+P)が大きい側をAとし、同点は長さ・端点による固定規則で決める。これは塩基対の「レベル」とは別。アンカーの選び方は学習係数や選択結果に依存させない。

refinement後の疎行列は条件付き値を既存値へ加算しており、値が1を超え得る。ここではPをBPP由来の支持値と呼び、例えば `c(P)=P/(1+P)` で特徴用に有界化する。これは確率の校正ではない。raw Pのlogitや `1-sum(P)` を用いない。

各対(i,j)の相手特異性は

\[
r_{ij}=\operatorname{clip}_{[-3,3]}
\min\left\{
\log(P_{ij}+\epsilon)-\log(m_{i\setminus j}+\epsilon),
\log(P_{ij}+\epsilon)-\log(m_{j\setminus i}+\epsilon)
\right\},
\]

とする。mはその端点の別の対合相手の最大支持値。上位二つの相手をあらかじめ保持すれば、対象相手を除いた最大値は定数時間で得られる。疎行列にない相手についてはcutによる欠測を扱う。[ProbKnot原著](https://rnajournal.cshlp.org/content/early/2010/08/10/rna.2125310.full.pdf) は両端で相対的に最も支持される対を使う先例だが、このlog比を交差相手の特徴へ組み込む式は今回の提案である。

最初のモデルは `delta_theta(A,B)=theta^T f(A,B)`。候補特徴を次に絞る。

| 特徴 | 区別したい状況 |
|---|---|
| 切片 | 平均的な交差補正 |
| A,Bの平均支持の積・差 | 二本の同時支持と非対称性 |
| Bの相手特異性の平均・下位分位 | 弱いが相手が明確／対合先が曖昧 |
| Aの支持×Bの特異性 | 強い交差相手があるときだけ信頼できる対 |
| 飽和した短い方のステム長 | 偶発的な短ステム、過剰な長さ加点 |
| Bの支持のばらつき | 一部の対だけが支える候補の延長 |
| 外側ループ／相手ステム長、中央ループ | 交差の局所形状 |
| Bに交差可能な候補ブロック数 | 多数の相手から加点が累積する曖昧さ |

実際に採用する特徴数は8〜12に制限し、初期とrefinement後を別に検証する。初期支持とその後の増加を使う対照は、誤った初期構造による自己強化を識別する候補となる。通常のステムエネルギーやGC率、CC−DPは必要な場合の追加対照とし、BPPの情報を単純に二重加算しない。

### 一対あたりの配分

現実装の完全な二ブロックに対する補正Phiは、部分選択で `Phi*kA*kB/(A*B)` となる。この形を使い、**`Phi=|B|*delta_theta(A,B)`** とする。

\[
w_{ab}=\frac{\Phi}{|A||B|}
=\frac{\delta_\theta(A,B)}{|A|},\qquad
\Delta S=\delta_\theta(A,B)\frac{k_A}{|A|}k_B.
\]

Aが全部選ばれれば、Bの選択された塩基対一つにつきdeltaが入る。固定Phiでは一対あたりPhi/Bだったため、長い弱ステムほど補正が薄まる。元の塩基対利得との単位も合わせやすい。対照として現行の固定Phiと `Phi=min(|A|,|B|)*delta` を残す。

重みは物理的な交差辺に一度付け、どちらの変数が上位レベルに選ばれても同じ値にする。アンカーAを上位レベルと同一視しない。元の支持行と符号付き線形化を維持するので、追加整数変数0、支持行あたり高々一連続変数・四制約という上限は変わらない。

複数のアンカーを選んだ場合の加点は加算される。次数特徴はこれを識別するが、合計額の厳密な上限にはならない。必要なら、入力だけから決めた `pi_AB`（Bの相手について和1）を掛ける対照を使う。選ばれない偽候補にも分母が増えるため、真のアンカーの補正を薄める副作用があり、無条件には採用しない。

## 学習を推論の目的関数に合わせる

まず実際の候補で、交差接点の `y_a*y_b`、またはブロック内の正解占有率の積を教師にして、少数特徴・正則化モデルの識別力を調べる。PKフリー参照の候補と、デコーダが実際に選びやすい誤候補を負例に入れる。「両ステムが完全正解」の二値教師は部分選択の実装と一致しない。

最終的には元の単独塩基対利得S0を固定し、構造間の残差だけを学習する。

\[
S_\theta(y)=S_0(y)+\theta^T F(y),\qquad
F_j(y)=\sum_{A,B}f_j(A,B)\frac{k_A(y)}{|A|}k_B(y).
\]

既存デコーダを使うmax-margin学習には [Akiyama・Sakakibara・Sato (2022)](https://mdpi-res.com/d_attachment/genes/genes-13-02155/article_deploy/genes-13-02155.pdf) のIPknot型デコーダ＋SSVMの先例がある。ただし同論文はニューラルネットによる単独対の推論で、この小さな交差特徴モデルの改善を示したものではない。

学習の参照は、元の候補・レベル・連続対制約で実現可能な正解部分集合へ投影する。投影はthetaに依存させず、特徴を作る候補グラフは予測時と同じ完全なグラフを使う。最終精度は投影した参照ではなく元の正解に対して測り、候補欠落と制約による欠落を別に記録する。

固定BPP・固定候補・線形deltaなら通常の構造特徴によるSSVM目的を使える。特徴のclip・正規化は入力だけから決める。補正量を抑えるなら、各特徴を[-1,1]へ収めて `||theta||1<=delta_max` とする。出力 `clip(theta^T f)` やtanhを使うと、通常の線形SSVMの凸性をそのまま主張できない。refinementでBPPがthetaに依存する全パイプラインも、固定特徴の凸問題とは異なる。

auto/refinementで同じRNA・接点を繰り返すので、RNA単位で重みを揃え、クラス均衡のために負例を間引く場合は確率・切片の校正も行う。少数の相関したモチーフを独立な大量標本とは数えない。

## 計算量と実装箇所

各BPP行列について一度だけ端点の上位二相手などを計算し、`PKPosteriorContext` として渡す。`PKLevelPairs` には現在BPPが入っていない。候補ステムの集計も一度行い、既存の幾何候補へ定数次元の特徴内積を追加する。初期の支持を残す場合は、特徴用の値を保存し、BPPを追加計算しない。

疎BPP数Pの走査はO(P)、候補塩基対Eのステム集計は索引込みでO(E log E)、既存の幾何候補Mへの内積はO(dM)、交差辺への配分は既存の処理。全前処理を支持辺数QだけのO(Q)と断定しない。追加のBPP計算・候補塩基対変数・推論時求解回数は不要。目的関数の変化による求解時間の増減は測る必要がある。学習時の追加求解は推論とは別に扱う。

最大候補ブロックの範囲外で正解交差辺が多く採点から落ちる場合は、既存の支持辺を、端点間隔・局所連続対数・相手特異性で直接採点するフォールバックを比較する。全部分ステムの列挙や形状の最大値選択は不要。適用辺が増えれば補助変数・係数も増えるので、線形個の上限が同じでも実測サイズは記録する。

## 最初の検証

1. 実際の各閾値・refinementで、正解対の候補被覆と採点される交差接点の被覆を記録する。候補cutはまず変えない。
2. 形状のみ、絶対BPPのみ、相手特異性＋アンカーとの相互作用の三モデルを比較する。旧Phi配分と一対あたり配分も切り分ける。
3. 家族または配列類似性クラスタを分けた交差検証で特徴・正則化・補正尺度を決める。PK対F1だけでなく全対F1、PKフリーRNAの偽PK数、求解時間を制約として見る。
4. 自動閾値・refinementを含む実際のパイプラインで検証する。従来のpseudo Fによる最後の選択が、学習したILPの候補を捨てる可能性もある。必要なら既存候補を使う小さいrankerを別条件で校正する。追加のILP/BPPは不要だが、単独利得とpseudo Fへ同じraw補正を無調整で足さない。
5. 特徴も重みも凍結してから新しい評価を実行する。以前の300配列はすでに観測済み。家族を分離した新しい評価を確保し、PK対F1差の家族単位の区間と時間を報告する。

初期候補の拡大は正解対の回復余地を増やすが、整数変数・制約を増やす。今回の最初の提案には含めず、スコア改善と候補拡大を別実験にする。

## 診断の再実行

```sh
python3 experiments/pk-score/analyze_pk_errors.py
```

初期BPPは調整用manifestの282配列だけをmulti-FASTAへ書き、次で出力した。閾値1・refinement0で候補変数は0となり、求解ログにも最適化呼出しは0だった。これは新しい精度実験ではない。

```sh
python3 - <<'PY'
import json
from pathlib import Path
directory = Path('experiments/pk-score/results/score-design')
directory.mkdir(parents=True, exist_ok=True)

tune = [entry for entry in manifest['entries'] if entry['split'] == 'tune']
assert len(tune) == 282 and sum(entry['positive'] for entry in tune) == 141
(directory/'tune.fa').write_text(''.join('>'+entry['id']+'\n'+entry['sequence']+'\n' for entry in tune))
PY
build/ipknot -r 0 -t 1 \
  --bpp experiments/pk-score/results/score-design/tune.bpp \
  --loglevel info experiments/pk-score/results/score-design/tune.fa

```

脚本は調整用ID・配列・座標を照合し、疎出力の欠測を0で補完しない。測定元ファイルとコードのハッシュを結果JSONに残す。学習や新スコアの求解・精度評価はまだ実行していない。
