# 長鎖DDの精度改善に向けた小規模実験（2026-10-05）

今回の例では、**反復数を増やすよりDP beamを広げる方が有効**だった。候補はまず`--dd-beam 200 --dd-max-iter 50`、精度を優先する場合はbeam 400。同じ初期BPP・固定閾値での実験でも探索不足を確認した。既定値とC++実装は変更していない。

2022年論文の[公式公開データ](https://zenodo.org/records/4923158)から16本を選び、計323実行を検査した。欠測・予測失敗は0。8本は前回のDD 50とILPのF1差で選んだ診断用、8本は予測差を使わず入力hashで選んだ確認用である。すでに評価した同じベンチマークの探索実験であり、関連配列も含む。平均値を全長鎖816本の改善量とは扱わない。

## 結果と使い分け

| 方式（beam / 反復上限） | 診断用8本の平均F1 | 確認用8本の平均F1 | 確認用で改善/同点/悪化 |
| --- | --- | --- | --- |
| ILP | 0.40498 | 0.34718 | 7/0/1 |
| beam 100 / 50 | 0.31911 | 0.32758 | 0/8/0 |
| beam 100 / 500 | 0.32426 | 0.33183 | 4/2/2 |
| beam 200 / 50 | 0.38797 | 0.33637 | 6/0/2 |
| beam 400 / 50 | 0.39000 | 0.34214 | 6/0/2 |
| beam 200 / 100 | 0.38794 | 0.34044 | 6/0/2 |

改善・同点・悪化はbeam 100 / 50との対応比較。ILPとbeam 100 / 500の精度は、同じバイナリ・同じ条件の前回全件評価から再利用した。beam 100 / 50を16本で再実行し、前回の予測構造と全て一致することを確認した。

beam 200と400は診断用8本すべてで改善した。確認用ではいずれも6本で改善、2本で悪化。400は確認用平均が高いが、3724 ntの例では100より悪化した。幅を広げれば参照F1が単調に上がるとはいえない。beam 200 / 100も一律には50よりよくならず、反復増加だけを第一候補にはしない。

1000/2883/562 ntの診断用3本を、同じCPU19で各3回逐次実行した。各配列の3回の中央値を合算。LPC・auto閾値・refinementを含み、traceとinfoログは無効にした。

| 方式 | 実時間中央値の総和(s) | 100 / 50との時間比 | 最大RSS(MiB) | 変動係数中央値 |
| --- | --- | --- | --- | --- |
| beam 100 / 50 | 12.838 | 1.000 | 134.11 | 0.15% |
| beam 200 / 50 | 23.085 | 1.798 | 134.11 | 0.09% |
| beam 400 / 50 | 37.603 | 2.929 | 134.11 | 0.31% |

この3例ではbeam 200は約1.80倍、400は約2.93倍の時間を要した。観測ピークRSSはほぼ同じだった。確率計算を含むプロセス全体のピークなので、DP単体のメモリ量が同じという意味ではない。

現段階で試す設定:

```sh
ipknot --decoder dd -e lpc -t auto,auto -r 1 \
  --dd-max-iter 50 --dd-patience 0 --dd-beam 200 input.fa
```

精度寄りの比較ではbeamを400にする。LPCの`--beam-size`は100のまま。DP beam、交差幅、反復予算に固定上限を置くため、既存DDの疎な入力に対する線形オーダーを維持できる。長さに比例してbeamを増やす方策は採用していない。今回の測定はpatience=0であり、既定の20で同じ結果とは保証しない。

## 原因の切り分け

### DP探索の不足

1000 ntの`bpRNA_RFAM_24847`は、FASTAからのauto/R1予測でF1が0.05096→0.24000→0.28261（beam 100→200→400、全て50反復）になった。beam 100で500反復に増やしても0.05096だった。

同じ初期BPP・同じ閾値`0.125,0.0625`・同じ交差グラフで比較:

| DP条件 | F1 | 回収目的値P | 証明上界U | 捨てたDP状態（反復合計） |
| --- | --- | --- | --- | --- |
| beam 100 / 50 | 0.14588 | 30.60211 | 111.90115 | 136566 |
| beam 200 / 50 | 0.12400 | 47.74494 | 106.06128 | 120395 |
| beam 400 / 50 | 0.30229 | 97.09125 | 106.06128 | 94208 |
| 枝刈りなしDP / 50 | 0.38261 | 103.56970 | 104.00322 | 0 |

枝刈りなしDPではF1=0.38261まで回復した。低い目的値と大きな枝刈りが、幅100での探索不足と整合する。ただしDPだけを厳密化した診断であり、交差グラフ制限と50反復は残る。整数最適性の証明ではない。beam 0は非線形な診断専用とする。また、200では目的値が上がってもF1が下がっており、最適化目的と参照F1は分ける必要がある。

### refinementが初期誤差を増幅する例

| 方式 | 同じ初期BPP・R0の平均F1 | FASTA・R1の平均F1 |
| --- | --- | --- |
| ILP | 0.40252 | 0.40498 |
| beam 100 / 50 | 0.34858 | 0.31911 |
| beam 200 / 50 | 0.38261 | 0.38797 |
| beam 400 / 50 | 0.39031 | 0.39000 |

562 ntの`URS0000D6B3B2_12908_1-562`では、DD側のR1後BPPをILPに渡してもF1=0.33019。逆にILP側のR1後BPPをDD 100 / 50に渡すと0.49785だった。4本でBPP交換を行い、元decoderへ渡した全8条件で元の構造を再現した。DP探索だけでなく、そこから作られた構造が次の確率計算に与える影響が大きい例がある。

したがってbeamの拡張は最終solveだけでなく初回から適用する。refinementを一律に切る方策は推奨しない。beam 200ではこの診断用群のR1がR0よりよかった。

### auto閾値のPKスコア近似

4本×3幅で全10閾値を固定BPPから解き、参照構造を使わず、全交差の確率積によるPK pseudo-Fで再選択した。12条件すべてで現在のsampled選択を再現し、全交差へ置き換えても選択閾値・構造は変わらなかった。これは今回の例での結果であり、近似の影響が全配列でないという意味ではない。完全計算はFenwick木による`O(n + M log n)`のオフライン診断で、線形時間の本体には導入していない。190ランダム行列と各3部分集合を、独立した二重ループの交差計算と照合した。

### その他の方策

| 方策 | 診断用8本の平均F1 |
| --- | --- |
| 対照 100 / 50 | 0.31911 |
| 交差幅400・witnesses64 | 0.31498 |
| 追加回収を10反復ごと | 0.31440 |
| DDで孤立対を許す | 0.31093 |
| ILPで孤立対を許す | 0.39731 |

交差グラフの拡張は制約とPK pseudo-Fの両方を変える比較である。追加回収、孤立対許容とも今回の群で一律の改善にはならなかった。562 ntでは孤立対許容DDが0.54745へ改善した例もあるが、1000 ntの大きな差は解消しない。DDとILPの孤立対禁止制約の意味は異なるため、これを原因の否定やモデル同値性の証明とは扱わない。

## 次に進める方策

まず長鎖だけを対象にbeam 200/400・50反復を全816本で比較し、特に今回悪化した種類を確認する。その結果を基に、長鎖のbeamを固定上限まで段階的に広げる設定を検討する。次にrefinementに入る前の初期解を改善する。全交差pseudo-Fや孤立対制約の変更を最初の既定変更にはしない。現時点の少数例だけで既定値は変えない。

## 保存物と検査

[実験ディレクトリ](../experiments/dual-decomposition/long-accuracy/README.md)に全16参照、全323予測、初期/交換BPP、閾値ごとのスコア、上下界・枝刈り診断、環境とchecksum、再実行スクリプトを保存した。FASTAとBPP以外の参照情報を予測器に渡していない。精度を再計算し、塩基使用の排他性、DDの隣接対支持、入力・バイナリのchecksum、全条件の存在を検査した。C++の変更がないため既存CTestの再実行は行わず、新しいスコア診断の2テストを実行した。
