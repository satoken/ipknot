# IPknot DDの上界・下界改善（2026-10-04）

以下は6582569時点の比較。ここで挙げた次の候補を実装・評価した結果は[整数ギャップと次の上界・下界](dual-decomposition-integer-gap.md)に記録した。

今回の目的は、固定した疎な候補・交差支持グラフに対し、最適性の証明に使う上界を締め、実行可能な整数解から得る下界を上げることで、同じ精度に必要なDD反復を減らすことである。ブロック内の厳密DP、全レベル共通の塩基容量上界、複数のレベル0構造からの解回収を実装した。ビーム幅、ブロック幅、履歴幅、反復予算を固定すれば、いずれも疎な入力に対する線形計算量を保つ。

生物学的な予測精度、従来ILPとの一致、整数目的値、DD緩和LPとのgap、実行時間は別々に評価する。上界が締まっても、整数ギャップやビームの探索不足が消えるわけではない。追加機能の既定はoffにし、既存の目的関数と候補グラフを変えずに比較できるようにした。

実測では、静的全体上界が最も軽い。59配列の236固定閾値条件で最終構造を保ち、最終gapの合計を約32%縮めた。自動閾値選択ではDD反復を9.45%減らした。ブロック上界は証明を増やす一方、追加回収は目的値を改善しても計算を増やす。以下ではこの違いを数式・実装・同一問題上の実験で分けて示す。

## 1. 前回の検討から分かった不足

[収束検討](dual-decomposition-convergence.md)では、次を切り分けた。

- 回収した整数解が十分良いか。
- DD緩和のLP自体に整数ギャップがあるか。
- 乗数が十分良いか。
- 証明上界が厳密な双対値をどれだけ過大評価しているか。
- ビームの部分問題値が厳密DP値をどれだけ過小評価しているか。

従来のレベル別端点上界は、各塩基に接続する正の調整係数の最大値を取り、その総和を2で割る。候補同士の交差排除や孤立対禁止を無視するので、良い乗数・良い整数解が得られた後もgapを閉じられないことがある。枝刈りが実際に起きなかったDPを厳密オラクルとして使う `--dd-unpruned-bound` は有効だが、長い配列でビームが状態を捨てる場合には十分でない。

下界側では、従来の回収はその反復のレベル0の双対部分問題解を固定して、上位レベルを順番に組み立てる。一度レベル0を固定すると、上位レベルに必要な交差相手や、上位対のために空けるべき塩基を変更できない。DD乗数の改善だけで別のレベル0構造が現れることを待つため、整数解の回収に不足が残り得る。

今回の追加はこの2点に対応する。劣勾配に使う部分問題解と、証明用上界・実行可能解提案を混同しない。

## 2. 問題と上界の意味

候補対pの元の単項係数をw_p、レベルをℓ(p)、選択変数をx_pとする。レベルペナルティは既にw_pへ含める。保持したPK接触e=(u,l)の係数をc_eとし、目的関数を

```text
f(x) = sum_p w_p x_p + sum_e c_e x_u x_l
```

とする。各レベルの非交差、全レベル共通の塩基容量、各上位対の必要な下位交差支持、指定された孤立対禁止を満たす整数最適値をI*とする。各レベル構造の凸包とPK積因子の凸包を用いたDD緩和の最適値をD*とする。

乗数qでの厳密なラグランジュ値は

```text
L(q) = C(q) + sum_level max_(x in level structures) sum_p a_p(q) x_p
```

である。C(q)は容量乗数の定数項とPK積因子の最大値、a_p(q)は現在の調整係数。有限ビームの値B(q)は通常L(q)以下であり、B(q)を証明上界には使えない。

実行可能回収値の履歴最大をP、レベルオラクル上界から得る履歴最小をU_oracle、今回の静的全体上界をU_globalとすると、実数演算で

```text
P <= I* <= D* <= min(U_global, U_oracle) = U_total
D* <= min_t L(q_t) <= U_oracle
```

となる。**U_globalは特定の乗数でのL(q)を上から抑える必要はない。** U_totalが `min_t L(q_t)` より小さくても矛盾ではない。前回の4項gap分解はU_oracleに対して使い、U_totalへそのまま適用しない。

```text
U_oracle - P
  = (I* - P) + (D* - I*)
    + (min_t L(q_t) - D*) + (U_oracle - min_t L(q_t))

U_total - P
  = (I* - P) + (D* - I*) + (U_total - D*)
```

数学的な上界を保証する対象は、現在保持している候補・支持行・PK接触のグラフである。無制限の元ILPの上界とは限らない。特に負のPK接触の保持・削除は目的関数を変えるため、交差beamやwitness数を変えた比較は、単一問題上の単なる上界改善として扱わない。

## 3. レベル別のブロック上界

### 3.1 外部辺を端点クレジットで被覆する

配列を幅Wの連続ブロックへ分割する。同じブロックに両端が入る対を内部辺、それ以外を外部辺と呼ぶ。現在の調整係数a_pは正負を取り得る。

各塩基iに非負クレジットd_iを置き、すべての許可された外部辺p=(i,j)に対して

```text
d_i >= 0,  d_i + d_j >= a_p
```

を満たすようにする。負の外部係数には追加クレジットが不要である。内部係数を

```text
a'_p = a_p - d_i - d_j
```

へ変更し、各ブロックbの内部対だけを用いた非交差マッチング最適値をF_b(a')とすると、上界は

```text
U_block(a) = sum_i d_i + sum_b F_b(a')
```

になる。

証明は各実行可能レベル構造をブロック内部へ制限することから得られる。選択された外部辺の係数は両端のクレジットで抑えられる。選択された内部辺から引いたクレジットと、外部辺へ使うクレジットの合計は、塩基を高々1回しか使用しないため `sum_i d_i` 以下である。内部に残る構造は各ブロックの許容構造なので、その調整後スコアはF_b以下。ブロックを跨ぐ交差排除・構造制約を捨てることで緩和し、上界を得る。

単純に「内部は厳密DP、外部の正の対を全て加算」するより、端点の使用競合を残す点が強い。内部対もクレジットを支払うため、同じ塩基を内部と外部の両方で使う利益を無条件に二重計上しない。

### 3.2 3通りの初期被覆と固定回数の改善

現在の実装は次の3通りを試し、最小の上界を採用する。

|初期値|定義|得意な形|
|---|---|---|
|端点最大値の半分|d_i = max(0, max外部接続係数)/2|外部グラフ全体の一般的な被覆|
|左端へ配分|d_i = max(0, iを左端とする外部係数)|左端を共有する星型・疎な候補|
|右端へ配分|d_i = max(0, iを右端とする外部係数)|右端を共有する星型・疎な候補|

たとえば1つの塩基から17本の重み1の外部辺が出る星では、半最大値の被覆和は9になる。左端または右端へ配分する被覆は1で、実際のマッチング上限へ一致する。

各初期値について、前向き・後ろ向きの2回だけ塩基を走査し、

```text
d_i <- max(0, max_(i,j is allowed external) (a_(i,j) - d_j))
```

へ下げる。既存クレジットより大きくしない。これは外部辺の被覆を保つ。クレジットをδ下げても、内部マッチングはその塩基を高々1回しか使用しないため、内部最適値の増加はδ以下。クレジット総和はδ下がるので、実数演算ではU_blockを悪化させない。

この手順は外部辺の最小被覆LPを最適に解くものではない。たとえばクレジットの一時的な増加が必要な改善は、単調減少の座標走査だけでは到達できないことがある。3初期値を使う目的は、固定コストで異なる被覆を試すことである。無制限に被覆最適化する方針は採らない。

### 3.3 内部DPと孤立対禁止

通常版はブロック内の疎な候補に対し、正負のa'_pを用いる通常のNussinov DPを厳密に計算する。

```text
F(i,j) = max(F(i,j-1),
             max_(k,j allowed) F(i,k-1) + a'_(k,j) + F(k+1,j-1))
```

空構造のスコアは0。内部に限るのでW×Wのチャートで足りる。負の係数も残し、孤立対禁止時に利益のあるスタックを支える内側対を捨てない。

孤立対禁止をすべてのブロック内構造へそのまま課すことは不正である。実際のスタックがブロック境界を跨ぐと、内部に残った1対だけが孤立して見えるからである。

そこでP(i,j)は外側の親対からスタック支持を借りられる状態、Fは完成した構造とし、Pには

```text
P(i,j) = a'_(i,j) + max(F(i+1,j-1), P(i+1,j-1))
```

を用いる。Fへ入れる完成成分は原則 `a'_(i,j)+P(i+1,j-1)` とし、隣接内側対を要求する。ただし、対がブロックの左端または右端へ接し、外側対 `(i-1,j+1)` が配列内に物理的に存在し得る場合は `a'_(i,j)+F(i+1,j-1)` も許す。

内部対の隣接内側対は必ず同じブロック内にある。グローバルに有効なスタックから内部だけを残したとき、失う可能性のある支持は隣接外側対だけであり、その場合はこの境界例外へ入る。したがって元の孤立対禁止構造のすべての内部制限を含む緩和になり、上界は保たれる。

現在は、境界例外の外側対候補が実際に許可されているかまでは調べない。存在しない外側対の支持を借りることも許すため、保守的な余裕は残る。ブロックが配列全体を覆う場合には物理的な外側対が存在できず、通常版・孤立対禁止版とも該当する厳密レベルDPになる。

### 3.4 従来上界との関係と実行間隔

ブロック上界は従来の端点上界と最小を取る。ブロック幅を広げると内部DPが強くなる傾向はあるが、境界も変わるため、幅8・16・32・64の上界が一般に単調とは主張しない。同じ幅の異なる分割offsetを試して最小を取ることは安全である。ヘルパーAPIはoffsetを持つが、現在のCLI統合はoffset=0の1分割だけを使う。

`--dd-bound-block W` は1〜64で有効、0はoff。`--dd-bound-every K` は1以上で、初回・K反復ごと・最終反復、および間隔外の停留/停滞停止直前に評価する。全レベルが厳密DPなら追加計算は不要である。`--dd-unpruned-bound` を併用すると、実際の枝刈りが0だったレベルも既存DP値を上界に使い、ブロック評価を省く。

上界を毎反復計算すると、減らしたDD反復の利益を証明計算のコストが上回る可能性がある。WだけでなくKも測定対象にする。評価しない反復でも過去の最良上界は有効なので、証明の安全性は失われない。

## 4. 全レベル共通の静的上界

DDのレベル部分問題は塩基容量を乗数で緩和する。良くない乗数では、各レベルに同じ塩基を使用させた利益を双対値が大きく計上する。そこで現在の乗数と独立に、全レベル共通の容量を残す上界を一度計算する。

正の接触c_e>0について、binary変数なら

```text
c_e x_u x_l <= c_e (x_u + x_l) / 2
```

である。負の接触は `c_e x_u x_l <= 0` として捨てる。各対へ正の接触の半分を配った単項係数

```text
v_p = w_p + (1/2) sum_(positive contact e incident to p) c_e
```

を作る。全レベルの全候補に対して非負端点被覆h_iを置き、`h_i+h_j>=v_p` を満たせば、全レベル共通の塩基容量から

```text
f(x) <= sum_p v_p x_p <= sum_i h_i = U_global
```

となる。被覆の3初期値と前向き/後ろ向き走査はブロック上界と同じで、こちらでは全候補が被覆対象となる。

DD緩和のPK因子凸包でも積変数y_eは `y_e<=x_u` と `y_e<=x_l` を満たす。したがって `2y_e<=x_u+x_l` はLPにも有効であり、U_globalは整数解だけでなくD*も抑える。

### 4.1 強くなる例と残る余裕

同じ物理対に複数レベルの候補がある場合、レベル別の上界は各レベルの利益を別々に数える。全体上界はその物理的な塩基使用を高々1回に抑えるため、特に初期乗数で強くなる。

一方、PKの正の接触を単項へ配分すると、一方の対しか選ばない構造にも接触利益の半分を与えてしまう。負の接触を捨てるため、PKペナルティが強いモデルでは緩い。レベル内の交差排除、交差支持、孤立対禁止も捨てている。これらの要因から、全体上界が常にブロック上界より強いとは限らない。両方を保持して最小を取る。

### 4.2 オラクル・劣勾配へ混ぜない

`--dd-global-bound` は保持グラフの前処理後、solveあたり1回だけ計算する。各反復のL(q)やB(q)の代用にせず、最良証明上界と停止判定だけへ入れる。

特にU_globalがL(q)より低くても、`U_global-P` をPolyakステップの分子へ代入しない。その差は現在のラグランジュ関数の誤差ではないためである。上界計算は候補選択、調整係数、劣勾配、ステップ更新を変更しない。上界のみを有効にした同一設定は、新しい証明停止が起きるまでは元と同じDD軌道をたどる。

## 5. 5種類のレベル0シードによる下界回収

従来の回収は毎反復続け、その上で追加のシードを一定間隔で試す。シードは次の5種類である。

|シード|レベル0の提案係数|狙い|
|---|---|---|
|original|元のw_p|乗数に依存しない利益のある骨格を基準にする|
|mean|直近最大8反復のレベル0調整係数の平均|乗数の振動で交互に現れる骨格を緩和する|
|selected_upper|元係数へ現在選ばれた上位対の正の機会利益を分配|現在の上位解へ交差支持を提供する|
|all_upper|全許可上位対の正の機会利益を分配|双対部分問題が選んでいない上位構造も試す|
|upper_opportunity|selected_upperに、上位対の端点を塞ぐ機会費用を加える|交差支持を作る利益と、上位対の塩基を奪う損失を両方見る|

originalは最初に1回計算して回収結果をキャッシュする。meanの履歴はレベル0候補の調整係数だけを最大8個保持し、反復数には比例させない。同じレベル0選択集合が複数提案から出た場合は、同じ回収を繰り返さない。

上位対の機会利益は、その単項係数と該当PK接触係数の和が正の場合だけ使い、必要な下位支持行とその行の代替witnessへ分配する。これは提案係数なので、複数の競合する上位対の利益を同時に見込むことがある。upper_opportunityでは、現在選ばれた上位対の正の単項係数を各端点の最大値へ集約し、レベル0がその端点を使うときに両端の和の半分を引く。

これらの機会利益・機会費用は整数解の候補を変えるためのヒューリスティックであり、上界ではない。特に負のPK接触や上位候補の重複があると過大・過小な推定になり得るため、機会費用なしの提案も残す。

### 5.1 実行可能性を保つ完成手順

各シードのレベル0構造をDPで作り、レベル1以降を順番に完成させる。

1. 既に使われた塩基を対候補から除く。
2. 各上位対について、必要なすべての下位レベルの支持行に、既に選択した交差相手が少なくとも1つあるか確認する。
3. 選択済み下位対との接触係数を、正負とも上位対の元係数へ正確に加える。
4. この許可マスクと係数で、そのレベルの非交差・必要な孤立対禁止DPを解く。
5. 完成した構造を元のw_pと、選択された両端を持つすべての元接触c_eで再評価する。

提案係数を最終目的値として返さない。各ステップで塩基容量・必要支持・レベル内構造を満たすため、完成後は保持グラフの実行可能解になる。提案が負の元目的値になる場合は空構造を採用する。空構造は常に実行可能で0の下界である。

これは上位レベルの順次完成であり、全レベルを同時に整数最適化するものではない。後で有望な上位対が現れても、先に固定したレベル0対を戻すことはしない。5種類のシードの目的は、線形コストのまま、この不可逆な選択の前提を少数だけ変えることである。

### 5.2 返却用下界とステップ目標を分ける

提案は双対部分問題の選択集合・勾配を置き換えない。元の目的値を再評価した実行可能解が改善した場合だけ、返却用最良下界P_bestと返却構造を更新する。一方、Polyakの目標に追加回収値をそのまま使うと、ステップ幅と後続のDD軌道が変わる。回収候補が良くても、その後の探索が変わった結果、同じ有限予算での最終目的値が元の実行より低くなる場合がある。

この干渉を避けるため、`--dd-recovery-target baseline|best` を設ける。追加回収を有効にした場合の既定はbaselineで、2つのincumbentを保持する。

```text
P_baseline = max_t 元の毎反復回収の目的値
P_best     = max(P_baseline, すべての追加回収の元目的値)
```

baselineではPolyak分子へP_baselineを使う。patienceの停滞カウンタは、元回収のincumbent改善または返却用P_bestの改善のどちらでもリセットする。追加提案によってpatience停止を後ろへ延ばすことはあるが、元回収が改善しているのに追加回収が停滞したことを理由に早く止めることはない。追加の成功を次の探索に活かす延長であり、max-iter予算は超えない。上界gapの停止には実行可能なP_bestを使ってよい。

追加計算の有無が元のDPや係数へ副作用を持たない限り、この方式は有効な証明gapで先に止まる場合を除き、元の実行が停止するまでの乗数軌道を保つ。patience延長後には、元の実行が存在しない反復まで同じ更新則で続ける。同じ固定予算まで走れば、元の全回収候補に追加候補を足すだけなので、返却目的値は元以上となる。証明gapで早く止まる場合は、元モデルの整数最適値との差が停止許容以内であるという上界の根拠を使う。この論理の数値範囲は後述の浮動小数点scopeを引き継ぐ。

bestは従来の共有下界の考え方を残した実験設定で、P_bestをPolyak目標へ入れる。停滞カウンタはこの設定でも元回収または返却下界の改善でリセットする。下界改善がステップを縮めたり探索を延長したりするため、速く良い解へ到達する可能性がある一方、同じ有限予算で元以上になる保証はない。baseline/bestとも各実行内の返却下界は単調非減少だが、別実行の目的値の大小とは区別する。

`--dd-recovery-every K` は0でoff、正値では初回・K反復ごと・停止直前に追加回収する。すでに証明gapが閉じている場合は追加回収を省く。`--dd-recovery-mode original|mean|lookahead|all` で提案群を分け、費用に対する寄与を比較できる。lookaheadは3種類の上位利益提案を意味する。最終比較ではbaselineを主設定にし、bestはDD軌道への干渉を調べる別条件へ分ける。

## 6. 計算量と数値範囲

nを配列長、Mを全レベル候補数、Eを保持接触数、Lをレベル数、Wをブロック幅、BをDPビーム幅、Hを回収履歴幅とする。

|処理|時間|追加記憶|
|---|---|---|
|レベル別ブロック上界1回|O(L*n*W + W*M + M)|O(L*n + M + L*W²)|
|全体静的上界1回|O(n+M+E)|O(n+M)|
|追加回収1バッチ|固定5提案、通常のビームDPと支持接触走査|O(n+M+E+H*M_0)|

各内部辺はその右端のDP列で高々W個の開始位置へ寄与する。チャートは1ブロック分だけを使い回す。外部被覆の初期値は3、座標走査は2回で固定する。シード数5、履歴H=8も固定する。従ってL、W、B、交差beam、witness数、H、反復数Tを固定すれば、合計は疎入力に対してO(T*(n+M+E))、記憶量はO(n+M+E)である。

「線形」は固定幅・固定反復予算の主張であり、任意精度に到達するまでの反復数や、Wをnまで増やす設定を含まない。`--dd-beam 0`、無制限交差グラフ・witness、配列全体を覆う厳密DPは小規模診断用である。BPP生成とrefinementも、この復号器の計算量とは分ける。

### 6.1 外向き丸めと保証の範囲

新しい被覆・ブロックDP・全体上界では、必要な加減算を `std::nextafter(...,+infinity)` で外向きに丸める。端点クレジットの半分がsubnormal領域へ入る場合も保守的に切り上げる。大きな正の和がoverflowすると上界は+infinityになり、有限値へ切り捨てて誤った証明停止を起こさない。負の内部対を保持し、完成した非正の成分だけを省く。

これはIEEEの通常演算を前提とし、fast-mathで演算を変形するビルドは対象外である。ブロックヘルパーは**渡されたbinary64調整係数を厳密な実数として解釈した問題**の保守的上界を計算する。既存DDの調整係数生成、定数C(q)、従来端点上界とのmin、元目的値の再加算は全経路を区間演算化していない。したがって現行予測器の最終gapを全元係数に対する形式的な区間証明とは呼ばない。

全体静的ヘルパーは元のbinary64単項係数・接触係数から外向き計算するため、ヘルパー単独ではその元モデルを直接抑える。一方、統合された最良上界は既存の通常丸め証明値とのminも含む。この違いを保ち、LP照合の数値許容と数学的証明を同一視しない。

### 7.4 独立ユニット検査

`tests/dd_bounds_test.cpp` は200個の長さ2〜9のランダム問題で、符号付き係数・許可マスク・2レベル、幅1/2/3/4/8/16/32/64と2offsetを調べる。独立な物理マッチング全列挙から通常/孤立対禁止のレベル最適値を求め、上界を照合する。全体上界はレベル間交差を許した一般の物理マッチングと、元の正負PK積を全列挙して照合する。星型、交差排除、境界スタック、負の内側対、極小subnormal、overflow、10万塩基の疎入力も含む。

独立のFraction診断ではbinary64係数を有理数へ正確に変換し、2,000ランダム問題に対するブロック/全体の計4,000検査を許容誤差0で行った。指数範囲-1072〜1020、±1e308、±最小subnormal、マスク、通常/孤立対禁止を含み、下界化・NaNは見つからなかった。これも既存DD係数生成を含む全経路証明ではない。

## 8. 今回の実装と今後の強化を分ける

### 8.1 次に安く試せる上界改善

現在の幅W・offset=0に加え、offset=W/2の分割も評価して最小を取れる。クレジット被覆を複数の決定的順序で減らすこと、境界の孤立対例外を実在・許可された外側候補がある場合だけに絞ることも、固定回数なら線形性を保つ。これらは同じレベル緩和の証明を強めるので、DD緩和LPの整数ギャップ自体は閉じない。

全体被覆を一般グラフの重み付きマッチングや被覆LPで厳密化すれば、端点競合をさらに正確に扱える。ただし正PK積の単項化による余裕は残る。グラフ全体を厳密に解く一般的アルゴリズムは、現在の固定予算の線形時間を保証しない。小さなブロックだけで一般マッチングを解いて外部端点被覆と合わせるなら、固定Wの線形計算量へ戻せる。

このうち、単なる端点被覆LPの最適化と、整数の一般マッチング最適値は区別する。後者の実行可能集合は、塩基容量だけのfractional matchingより強い奇数集合制約も含むため、元のDD緩和にはないレベル間の整数結合を表せる。単項化したv_pで一般マッチングを厳密に解いた値は、すべての元の整数構造を含むのでI*の上界だが、D*の上界である必要はない。DDの整数ギャップを締められる場合がある一方、正PK単項化が緩ければ効果は小さい。窓内の一般マッチングは、全レベルとPK接触を同時に列挙する窓DPより簡単な段階的候補になる。

### 8.2 DD緩和LPより強い証明へ進む場合

今回のブロックオラクル上界と全体単項被覆は、どちらもD*以上の上界である。したがってD*-I*>0の問題で、整数解の最適性までgapを閉じることはできない。

整数ギャップを縮める候補は、短い連続窓内で複数レベルの構造とPK因子を**同時に**列挙・最適化することである。窓内の塩基容量、支持、接触を独立因子の凸包より強く結びつけ、窓外との関係だけを端点・境界変数で緩和する。固定幅Wなら窓あたりの計算量がWに依存する大きな定数になっても、nに対しては線形に保てる可能性がある。

ただし次の設計が必要であり、今回の実装には含めない。

- 窓を跨ぐ長距離対を無条件に削除すると、元問題の上界ではなくなる。外部対・支持・接触の利益を保守的に被覆する境界状態が必要。
- 正の窓外PK接触は端点配分で上界化できる。負の窓外接触を捨てれば安全だが、整数ギャップ改善が薄れる可能性がある。
- 窓内の上位対が窓外下位対から支持を受けられることを許す必要がある。支持制約を窓内だけへ強制すると、正しいグローバル解を誤って除く。
- 重複窓を使う場合は、単項・PK接触をどの窓へ割り当てるか決め、二重計上を避ける。すべてのグローバル実行可能解が各窓の緩和へ射影できることを証明する。
- 完全列挙の定数はレベル数・Wに対して急増する。幅8〜16などの小窓から、小規模I*/D*で上界の安全性と実効的なgap改善を確認する。

窓を結合した強い緩和が元のDD緩和より低い上界を持つ場合、その値もL(q)の代用にはしない。証明専用として使うか、追加の一貫性変数とそれに対応する新しい双対問題を明示的に設計する必要がある。

### 8.3 下界の次の候補

上位構造からレベル0へ戻る局所交換、固定幅窓内の複数レベル再最適化、スタック単位の差し替え、少数の異なるビーム順位を使うシードは、今回の順次完成が戻れない選択を修正できる可能性がある。いずれも塩基容量とすべての支持行を再確認し、元の正負接触係数で再評価してから採用する。交換回数・窓幅・提案数を固定し、入力全体の整数ILPを予測経路へ再導入しない設計を目指す。

速度・証明を重視する最初の設定は `--dd-unpruned-bound --dd-global-bound` とする。globalは一度だけの線形走査で、自動閾値に効果があり、構造を変えなかった。全体上界が既に十分低い場合は、重いブロック上界を毎回計算する利益が小さい。

回収は品質を重視する任意設定とし、baseline目標を保つ。毎10反復のallは幅広い提案を持つが、既定としては費用が大きい。今回の36条件では初回＋停止直前の回収が同じ改善を約2.7%の費用で保持したため、まずこの疎な回収を品質設定として使う。mean単独・original単独・lookaheadの寄与が異なるため、必要な提案だけを選び、回収間隔を長くする比較を優先する。次に実装コストが小さい改善は、固定all-upper提案のキャッシュと呼び出し側DPチャートの共用である。これらは数学的な緩和を変えずに費用とRSSを下げられる。

証明率をさらに上げるには、step幅を調整する前に、24件の整数ギャップと狭いbeamの探索不足を分ける。整数ギャップには短窓の全レベル整数結合、探索不足にはビーム順位や局所交換が必要となる。今回の追加機能の既定はoffに保ち、品質・gap・wall-timeの目的に応じて有効にする。

## 9. 実行例と保存物

速度・証明を重視する設定と、疎な追加回収を有効にする設定例。予算とグラフを固定した比較に対応する。

```sh
# 軽い上界を有効にする
ipknot --decoder dd --dd-max-iter 500 --dd-patience 0 \
  --dd-unpruned-bound --dd-global-bound input.fa

# 初回と停止直前に追加回収し、従来のステップ目標を保つ
ipknot --decoder dd --dd-max-iter 500 --dd-patience 0 \
  --dd-unpruned-bound --dd-global-bound \
  --dd-recovery-every 500 --dd-recovery-mode all \
  --dd-recovery-target baseline input.fa
```

ブロック上界は `--dd-bound-block 32 --dd-bound-every 10` で別に追加できる。上界だけの影響を調べるときはrecoveryをoffにする。下界だけの影響を調べるときはblock/globalをoffにする。短い厳密比較ではbeam=0と全交差支持グラフを使えるが、線形時間設定とは区別する。

実装は `src/dd_bounds.h/.cpp`、`src/dd_recovery.h/.cpp`、統合は `src/dual_decomposition.cpp`。単独テストは `tests/dd_bounds_test.cpp` と `tests/dd_recovery_test.cpp`。前回資料は [DD設計](dual-decomposition.md) と [収束検討](dual-decomposition-convergence.md)。

保存先は[experiments/dual-decomposition/bounds](../experiments/dual-decomposition/bounds)。[集計JSON](../experiments/dual-decomposition/bounds/summary.json)、[全設定表](../experiments/dual-decomposition/bounds/summary.md)、[provenance](../experiments/dual-decomposition/bounds/provenance.json)に、ソース・バイナリ・固定BPP・モデルのSHA256を記録した。主報告はexact-500、real-100、real-500、auto-500、timing-500、timing-auto-500、cadence、scaling。入力は前回の[budget.json.gz](../experiments/dual-decomposition/convergence/budget.json.gz)内のBPPをそのまま使う。再学習・BPP再生成はしない。

```sh
cmake -S . -B build-dd -DCMAKE_BUILD_TYPE=Release -DENABLE_ILP=OFF
cmake --build build-dd -j 4
ctest --test-dir build-dd --output-on-failure

python3 experiments/dual-decomposition/bounds/rational_audit.py \
  --driver build-dd/dd_rational_bound_driver --output rational.json
python3 experiments/dual-decomposition/bounds/experiment.py exact \
  --driver build-dd/dd_bounds_driver --highs /path/to/libhighs.so \
  --output exact-500.json.gz
python3 experiments/dual-decomposition/bounds/experiment.py real \
  --binary build-dd/ipknot --baseline /path/to/frozen-parent-ipknot \
  --output real-500.json.gz
python3 experiments/dual-decomposition/bounds/experiment.py real \
  --binary build-dd/ipknot --baseline /path/to/frozen-parent-ipknot \
  --auto --limit 19 --output auto-500.json.gz
python3 experiments/dual-decomposition/bounds/cadence.py \
  --binary build-dd/ipknot --baseline /path/to/frozen-parent-ipknot \
  --timing-fixtures experiments/dual-decomposition/bounds/cadence.json.gz \
  --output cadence.json.gz
python3 experiments/dual-decomposition/bounds/summary.py \
  --directory experiments/dual-decomposition/bounds \
  --output summary.json --markdown summary.md
```

exact.pyのLP照合だけがオフラインでHiGHSを使う。予測バイナリはENABLE_ILP=OFFで生成し、共有ライブラリ依存も標準C/C++・数学ライブラリのみである。CPU affinity既定19がない環境では各実験へ `--cpu` を渡す。実時間比較は `experiment.py timing` に同じ入力ID、予算、対照バイナリを指定し、`--auto --limit 19` で自動閾値版を再現できる。
