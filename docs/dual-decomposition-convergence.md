# IPknot DDの収束検討（2026-10-04）

上界・下界の追加改善と、その証明・実測比較は[上界・下界改善の検討](dual-decomposition-bounds.md)を参照。前回の実装・収束実験は以下に保存する。

実配列59本の固定閾値236条件では、patienceを無効にした500反復と1000反復の返却構造・目的値が全条件で一致した。しかし、これを双対最適値への収束や整数最適性の証明とは扱わない。幅100のDP探索自体が不足する長い配列があり、上界の緩さとDD緩和の整数ギャップも残る。

今回追加した診断、枝刈りなし上界、減衰ステップはすべて既定off。従来の速度を重視する設定を維持した。前回保存した76予測（固定閾値38・自動閾値38）と今回の既定設定の予測は全て一致した。停止名 `stationary` は `beam_stationary` / `exact_stationary` に分けた。

## DAFSの検討から引き継いだ方針

ローカルDAFSの `docs/dafs_linearalifold_dd_convergence_2026-09-19_ja.md`、`docs/dafs_dd_recovery_2026-09-20_ja.md`、`docs/dafs_dd_certificates_2026-09-20_ja.md` と診断スクリプト・実装を読んだ。

- 返却解の実行可能性と、最後のDD部分問題間の不一致を区別する。
- ビーム内停留、回収解のplateau、双対最適化、証明上界の緩さを区別する。
- 小さい固定問題で整数最適値、DD緩和のLP最適値、保存された係数での厳密双対値を別々に計算する。
- 上界の改善を勾配やステップ更新へ混ぜず、独立の停止検査に使う。
- 追加機能を実測前に既定化しない。停止許容幅を緩めて収束したことにしない。

DAFSではprojected normが不利な検討結果があったが、IPknotでは同じ結論を仮定せず両方式を比較した。今回の小規模検査ではprojected normのPolyak更新の方が平均双対誤差は小さく、実配列でもfull normは反復数が増えた。返却解の品質には双方に勝敗がある。

## 何を収束と呼べるか

固定した保持グラフの整数最適値を `I*`、各レベルの完全な構造の凸包とPK接触因子の凸包を使ったDD緩和のLP最適値を `D*`、乗数qでの厳密な双対値を `L(q)` とする。回収した実行可能解の最良値をP、証明用上界の履歴最小をUとすると、数学的には

```
P <= I* <= D* <= min_t L(q_t) <= U
```

となる。ビームのラグランジュ値は `L(q)` 以下の近似値であり、この鎖の上界には使えない。上界gapは次の4項に分解できる。

```
U - P = (I* - P)                       回収解の不足
      + (D* - I*)                     DD緩和の整数ギャップ
      + (min_t L(q_t) - D*)            乗数最適化の不足
      + (U - min_t L(q_t))             証明上界の余裕
```

さらに、各反復で `L(q_t) - beam_L(q_t)` を測り、DPオラクルの近似誤差を分ける。保持グラフを変える比較は別の問題になる。特に負のPK接触を落とすと目的関数も変わるので、witness数を増減した目的値を同じ最適化問題の改善量と解釈しない。

実装のPolyak型更新は整数実行可能下界Pを目標にする。整数ギャップが正ならPはD*より低く、通常の既知最適値を使うPolyak法の収束条件を満たさない。beam_Lも厳密双対値ではない。1000反復まで増やしても、一律の大域収束保証は得られない。

`--dd-schedule diminishing` は

```
eta_t = dd_step * scale / (t^0.75 * sqrt(norm_squared))
```

を使う。scaleは元の単項・接触係数の最大絶対値（最低1e-3）で固定する。固定した有限グラフで勾配成分は整数かつ有界なので、ゼロでない使用ノルムは1以上、有限の一定値以下になる。したがって非零更新のetaは二乗和が有限・総和が無限となる。厳密部分問題、固定グラフ、早期停止なし、反復数を無限に伸ばす理想化の下で、射影劣勾配法の双対値の収束条件を満たす。整数解回収や有限ビームにはこの保証を広げない。基本条件の出典は [Boyd, Subgradient Methods, §§2–4, 6](https://stanford.edu/class/ee364b/lectures/subgrad_method_notes.pdf)。

固定Tによる線形時間と、任意精度まで収束するまでの反復を両方保証する主張はしていない。ビーム・グラフ幅・反復予算を固定すれば、追加機能込みでも疎な入力に対する計算量は従来通り `O(T*(n+M))`、記憶量は `O(n+M)`。

## 診断機能

`--dd-trace FILE` は予測開始時にFILEを作り直し、各solveのproblem、iteration、summaryをJSONLへ書く。自動閾値選択・refinementの各solveは固有のsolve_idを持つ。候補ゼロのsolveはsummaryだけを書く。

各反復には現在の回収値、最良下界、beam_L、現在の証明上界、最良上界、全ノルム・射影ノルムの二乗、塩基容量違反数、下位交差支持違反数、PKコピー変数の不一致数、相補性残差、枝刈り数、更新幅、停滞数、停止理由を保存する。違反数は部分問題の解に対する値であり、返却する回収構造の違反数ではない。

`--dd-trace-state` を併用すると、候補と許可マスク、保持した支持行と接触スコア、ラグランジュ係数と定数、DP選択・回収選択も保存する。小規模厳密診断はこの状態を再評価する。履歴はストリーム出力であり、予測器のメモリに全反復を保持しない。状態ログのファイル量は `O(T*M)` になり得る。

停止理由は `bound_gap`、`beam_stationary`、`exact_stationary`、`patience`、`max_iterations`、`no_candidates`。`beam_stationary`、`patience`、`max_iterations` は最適性の証明ではない。

`--dd-unpruned-bound` はDP呼び出し中に実際に捨てた区間状態を数え、ゼロだったレベルだけDP値を上界に採用する。それ以外は従来の端点最大値上界を使う。回収用DPを再利用する前に判定する。追加DPはなく、候補・勾配・更新ステップは変更しない。新上界がgapを閉じる場合だけ早く止まる。ゼロ値の状態が捨てられた場合も保守的に「枝刈りあり」と数える。

## 小規模の厳密照合

乱数seedは20261004。長さ8〜10の疎なランダム問題80、長さ11の正負PK接触を持つH構造40、長さ10の対称な競合候補8の計128問題。2〜3レベル、孤立対を許す/許さない条件を含む。

整数解は物理的なマッチングを独立に列挙した。LPは各レベルの構造を列挙した混合変数と、各PK積に対するbinary ANDの凸包制約を使う。HiGHSはこのオフラインLPだけに使用し、予測バイナリへのリンクはない。各反復の厳密双対値は列挙したレベル構造の最大係数和と保存された定数から求めた。

9設定×128 = 1152実行、321261反復を照合した。回収解の実行可能性・元係数での目的値、上界とLP/整数解の関係、厳密DPとの一致、ビーム値が厳密値以下、最良上下界の単調性を1e-7の数値許容で検査し、全て通過した。これは浮動小数点全経路の区間演算による形式証明ではない。

全交差グラフでは24/128問題に正の整数ギャップがあり、最大1.67885。主な1000反復の結果は次の通り。

|条件|整数最適解を回収|平均回収不足|平均双対最適化誤差|bound_gap停止|
|---|---:|---:|---:|---:|
|厳密DP、Polyak1.5、projected|125/128|0.002821|0.003251|96|
|厳密DP、Polyak1.5、full norm|125/128|0.002821|0.004504|90|
|厳密DP、Polyak0.5、projected|125/128|0.002821|0.004191|92|
|厳密DP、減衰、projected|127/128|0.000261|0.001791|95|
|厳密DP、減衰、full norm|125/128|0.002821|0.001125|96|
|ビーム2、Polyak1.5|98/128|0.299906|0.224636|32|
|ビーム100、Polyak1.5|125/128|0.002821|0.003251|32|
|ビーム100＋枝刈りなし上界|125/128|0.002821|0.003251|96|

この小さい集合ではビーム100は実際には枝刈りしない。従来上界の余裕だけで証明停止できなかった例が多く、枝刈りなし上界でbound_gap停止が32から96へ増えた。同じ回収解を保ったまま、停止の根拠を改善している。減衰方式の小規模での好成績を実配列全体の優位とは解釈しない。

幅2の交差グラフ・支持数2という別問題も同じ厳密診断で検査した。整数ギャップのある問題は27/128へ変わった。グラフ制限は単なる反復精度の設定ではない。

## 自動閾値・時間・線形性

例題3＋NMR16の19本×スコア2の38条件で自動閾値も比較した。500/1000、減衰500、幅200の500、枝刈りなし上界500の返却構造は全て一致した。既定設定は1条件（2MHI、learned）で異なった。固定閾値の各solveと同様、閾値探索の最終結果が一致しても、内部solve全てが双対収束したことにはならない。

枝刈りなし上界はこの38条件の内部solveのgap証明停止を208から306へ増やし、総反復数を37326から34731へ6.95%減らした。上界改善後のビーム内停留は7、反復上限は67 solve残った。

計測ログを外した別の逐次・交互順3回測定も保存した。2MHIのautoでは通常500反復と比べ約25.5%短縮（中央値0.04738→0.03529秒）。drzとASEのautoはほぼ同じであり、短いMIDV固定閾値のミリ秒差を一般的な高速化と解釈しない。全59本の精密な時間保証には使わない。

疎な長距離弧と繰り返しH構造の合成入力では、固定幅32・交差幅32・支持数8を使用。Polyak500反復は長さ1000/2000/4000/8000で0.507/0.931/1.916/3.813秒、RSSは約6.86/9.04/14.16/24.17MiB。固定反復の時間・メモリは線形スケーリングと整合した。これらの時刻にはtrace出力を含む。

この合成例は全て反復上限に達し、長さ8000ではP=412.65、U=776.38と大きなgapが残った。減衰500ではP=319.10、U=895.26で悪化した。線形に速く計算できることと、十分良い整数解・証明gapを得ることは分ける必要がある。

## 当面の使い方と残る課題

既定は速度優先のままとし、収束を丁寧に見る比較では次の設定を使う。

```sh
ipknot --decoder dd --dd-max-iter 500 --dd-patience 0 \
  --dd-unpruned-bound --dd-trace convergence.jsonl input.fa
```

長鎖で探索の不足を疑う場合は `--dd-beam 200` を同じ予算で比較する。乗数最適化の挙動を切り分ける実験では `--dd-schedule diminishing` も比較するが、これを推奨既定にはしない。厳密診断には短い問題に限定して `--dd-beam 0 --dd-crossing-beam 0 --dd-witnesses 0 --dd-patience 0 --dd-trace-state` を使う。これらの0設定は線形計算量を失う。

優先して残る課題は、ビームで落とした構造の回復、整数ギャップのある場合の回収提案、枝刈りが実際に起きる長鎖で使える安価な強い上界。今回は原因を分ける診断と小さな上界改善・別更新方式まで実装した。DAFSの平均履歴による回収やblock上界を未検証のまま移植して改善と称することはしていない。

## 保存物と再実行

`experiments/dual-decomposition/convergence/` に実験スクリプト、入力BPPと全予測、solve要約、代表反復、集計、provenanceを保存した。exactは全321261反復を検査した後、1/5/10/20/50/100/200/500/1000と最終反復を保存する。budgetも同じ代表点を保存し、元の全ログ件数をiterations_recordedに記録する。

```sh
cmake -S . -B /tmp/ipknot-dd-convergence-build -DENABLE_ILP=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/ipknot-dd-convergence-build -j8
python3 experiments/dual-decomposition/convergence/exact.py \
  --driver /tmp/ipknot-dd-convergence-build/dd_diagnostic_driver \
  --highs /path/to/libhighs.so --iterations 1000 --output /tmp/exact.json.gz
python3 experiments/dual-decomposition/convergence/budget.py \
  --source "$PWD" --candidate /tmp/ipknot-dd-convergence-build/ipknot \
  --baseline /path/to/pk-score/ipknot --archive /tmp/ipknot-dataset.zip \
  --cpu 19 --output /tmp/budget.json.gz
python3 experiments/dual-decomposition/convergence/supplement.py \
  --source "$PWD" --candidate /tmp/ipknot-dd-convergence-build/ipknot \
  --baseline /path/to/pk-score/ipknot --archive /tmp/ipknot-dataset.zip \
  --cpu 19 --output /tmp/supplement.json.gz
python3 experiments/dual-decomposition/convergence/summarize.py \
  --exact /tmp/exact.json.gz --budget /tmp/budget.json.gz \
  --supplement /tmp/supplement.json.gz --output /tmp/summary.json
```

CPU番号は実行環境に合わせる。HiGHSのctypes診断は32/64bit整数ABIを確認する。通常の予測器・CTestはこのPython診断のHiGHS依存を持たない。候補・対照バイナリSHA256、アーカイブSHA256、CPU affinity、ソースSHA256はprovenanceと各報告に保存した。時間測定の対象はBPP固定後の復号で、refinementと確率生成は含まない。

検証はsolverなしCTest5/5、HiGHS併用CTest63/63、DDコアのASan/UBSan。サニタイザでは実行環境の制約からleak検査だけ無効にした。
